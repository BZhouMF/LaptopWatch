# 数据库遍历逻辑重构 — 实现方案

## 目标

所有模式统一为「用到才核实、DB 驱动遍历」模型，删除启动时全量扫描，改为文件夹按需遍历。

## 涉及模式

| 模式 | 改动范围 |
|------|---------|
| Normal | 不改 |
| Video | 大改 — 删除 sync_database，新增 traverse_media |
| Image | 同 Video |
| Douyin | 中改 — 同上框架，每次 1 条 + 排除已播放 + 两种子模式 |
| Category | 中改 — 预览递归取，网格页复用 traverse_media，删缓存层 |

## ✅ 任务 2：新增 `traverse_media` 遍历函数

**文件**：`utils/db_utils.py`

**目标**：从根文件夹出发，按文件夹排序逐个遍历，sync_folder 核实后从 DB 取直接子媒体文件，凑满 limit 条后停止。

**函数签名**：
```python
def traverse_media(conn, root_path, media_type, offset, limit,
                   sort_type='name', sort_order='asc',
                   random_start=False, exclude_paths=None):
    """返回 (items, next_offset, has_more)

    items: [{name, relative_path, is_video, is_image, ...}]
    """
```

**内部流程**：
1. `_ensure_node` 确认根路径的祖先链
2. `sync_folder(root_path)` 核实根目录
3. `get_subfolder_nodes` 获取排序后的子文件夹列表
4. 随机模式：轮转文件夹列表
5. 构建遍历序列：[根目录直接文件] + [子文件夹1] + [子文件夹2] + ...
6. 遍历序列，每个段落先 sync_folder 再 get_direct_media
7. 跳过 offset 个文件，收集 limit 个文件
8. 格式化返回（相对路径、is_video/is_image 标记）

**验证**：写单元测试，模拟多文件夹场景，验证分页断点、随机起点轮转。

## ✅ 任务 3：更新 Video/Image 模式 API

**文件**：`blueprints/core.py`（index 路由）、`blueprints/media_api.py`（load_more）

**目标**：Video/Image 首页和加载更多改为调用 `traverse_media`，删除对 `sync_database`、`get_media_page`、`get_random_media` 旧调用方式的依赖。

**改动**：
- `index()` 中 Video/Image 分支：`traverse_media(conn, MEDIA_DIR, media_type, 0, PAGE_FIRST, ...)` 替代原来的 `sync_folder` + `get_media_page`/`get_random_media`
- `_db_load_more()`：`traverse_media(conn, MEDIA_DIR, media_type, offset, limit, ...)` 替代原逻辑

**验证**：运行 `test/test_media_api.py` 全部通过。

## ✅ 任务 4：更新 Douyin 模式 API

**文件**：`blueprints/douyin_api.py`

**目标**：`_pick_random_video` 改为调用 `traverse_media`，每次 limit=1，支持两种子模式。

**改动**：
- `DOUYIN_RANDOM_MEDIA=true`：`traverse_media(..., random_start=True, exclude_paths=history)`
