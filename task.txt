# LaptopWatch 数据库缓存层 — 方案与任务

## 设计原则

1. **不依赖 media_scanner.py**，该文件仅作测试用途
2. **惰性填充**：用户浏览到哪就缓存到哪，不预先全量扫描
3. **普通模式保持 emoji**：nodes 只存路径元信息，不存封面
4. **封面只在媒体模式生效**：images/videos 表有 cover BLOB，normal 模式不走
5. **每步有测试**：test/ 目录下对应测试文件

## 数据库设计

**数据库文件**：`db_path/{scope_name}.db`
（scope_name = MEDIA_DIR 的 basename，如 "Huawei Share"）

**三张固定表名**：

```sql
CREATE TABLE nodes (
    id          INTEGER PRIMARY KEY,
    parent_id   INTEGER NOT NULL DEFAULT 0,
    name        TEXT NOT NULL,
    type        INTEGER NOT NULL,         -- 1=folder, 2=file
    path        TEXT NOT NULL UNIQUE,
    size        INTEGER NOT NULL DEFAULT 0,
    extension   TEXT,
    create_time REAL NOT NULL,
    modify_time REAL NOT NULL,
    is_hidden   INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE images (
    id          INTEGER PRIMARY KEY,
    parent_id   INTEGER NOT NULL DEFAULT 0,
    name        TEXT NOT NULL,
    path        TEXT NOT NULL UNIQUE,
    modify_time REAL NOT NULL,
    cover       BLOB DEFAULT NULL
);

CREATE TABLE videos (
    id          INTEGER PRIMARY KEY,
    parent_id   INTEGER NOT NULL DEFAULT 0,
    name        TEXT NOT NULL,
    path        TEXT NOT NULL UNIQUE,
    modify_time REAL NOT NULL,
    cover       BLOB DEFAULT NULL
);
```

## 各模式数据流

### 普通模式 (normal)
browse 页面 → sync_folder(conn, path, 'normal') → 只更新 nodes → 前端根据 extension 显示 emoji
不走 images/videos，不走封面。

### 视频模式 (video)
页面加载 → sync_folder(conn, path, 'video') → 更新 nodes + videos → SQL 分页取视频列表 → cover 从 videos.cover 直接发 BLOB

### 图片模式 (image)
同上，images 代替 videos。

### 抖音模式 (douyin)
SQL RANDOM() 取视频，不再需要内存 dict。

### 目录浏览模式 (category)
SQL 查询替代递归 scandir，每分类块取 CATEGORY_PAGE_SIZE 条。

#### [x] 任务 1.2：sync_folder — 单文件夹增量同步

**目标**：用户点一个文件夹，只 scandir 该层，差异写入 DB

**内容**：
- `sync_folder(conn, folder_path, run_mode)`
  - 确保文件夹自身在 nodes 中存在
  - scandir(folder_path) 只 1 层，不递归
  - 比对 DB 子项：新增 INSERT、删除 DELETE、修改 UPDATE
  - 按 run_mode 决定是否同步 images/videos：
    - normal：只写 nodes
    - video：nodes + videos（文件夹也写进 videos，cover=NULL）
    - image：nodes + images
    - douyin：同 video
  - 封面生成数量不硬编码，但首次遇到就生成存 DB

**注意**：不调用 media_scanner.py，所有逻辑独立实现

**测试**：`test/test_sync_folder.py`
  - 空文件夹首次同步
  - 添加文件后再次同步（新增）
  - 删除文件后同步（删除）
  - 修改 modify_time 后同步（更新）
  - 子文件夹不递归
  - run_mode=video 时 videos 表同步
  - run_mode=normal 时不碰 images/videos
  - 删除文件夹时级联删除子节点

### 阶段 2：查询接口

#### [ ] 任务 2.1：文件夹/文件列表查询

**目标**：提供路由所需的分页、排序查询

**内容**：
- `get_children(conn, parent_id, sort_type, sort_order)` — 返回某文件夹下所有子项（文件夹 + 文件），支持 name/time 排序，asc/desc
- `get_media_page(conn, table, parent_id, limit, offset)` — 分页取媒体文件，table = 'images' 或 'videos'
- `get_random_media(conn, table, limit, exclude_paths=None)` — 随机取 N 个媒体文件

**测试**：`test/test_queries.py`
  - get_children 返回正确子项
  - 排序 name asc/desc 正确
  - 排序 time asc/desc 正确
  - 分页 limit/offset 正确
  - get_random_media 返回不同结果

---

#### [ ] 任务 2.2：封面读写接口

**目标**：封装 cover 的读写，供缩略图路由调用

**内容**：
- `get_cover(conn, table, path)` — 查某个文件的 cover BLOB
- `set_cover(conn, table, path, cover_data)` — 写入 cover
- `generate_and_cache_cover(conn, table, filepath)` — 生成缩略图 + 写入 DB + 返回

**测试**：`test/test_cover.py`
  - get_cover 返回 None 当没有 cover
  - set_cover 后 get_cover 返回正确数据
  - generate_and_cache_cover 对图片/视频均有效
  - 重复调用不重复生成

### 阶段 3：路由改造

#### [ ] 任务 3.1：normal_api.py — /api/list 走 DB

**目标**：normal 模式下列表从 DB 读取

**内容**：
- 在 `/api/list` 路由中，如果 DB 存在且有数据，从 nodes 表查询返回
- 如果 DB 不存在或无数据，调用 sync_folder 填充后再查
- 如果 DB 不可用，回退到现有的 get_sorted_folders() + get_files_in_folder()
- 返回数据结构不变，兼容前端

**测试**：`test/test_normal_api.py`
  - Flask test client 请求 /api/list
  - 返回结构不变
  - 首次访问自动 sync
  - 再次访问走缓存
